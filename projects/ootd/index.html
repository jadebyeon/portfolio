Wearby

A Playful OOTD Diary Companion for Daily Reflection and Emotional Well-Being

Wearby is an ongoing UX/UI design project that reimagines daily reflection as a small act of play. By combining outfit dress-up, a supportive companion character named Ear, and gentle journaling prompts, Wearby creates a calm emotional space where users can check in with themselves, reduce stress, and build meaning through everyday rituals. Currently in active development — the project spans end-to-end product design thinking, from research and user flow to a scalable Figma component library, design system, and WCAG-compliant accessibility standards.

Design Problem

Daily reflection tools often feel serious, effortful, or intimidating. Traditional journaling apps demand emotional labor, while fashion-tracking apps lack any meaningful well-being connection. Users who want gentle emotional check-ins are left without tools that feel approachable and low-pressure.

The challenge was to design a mobile experience that supports mental and emotional well-being through play — making daily reflection feel as natural and fun as dressing up a character.

Research & Strategy

Well-Being Research

Secondary research grounded the design in evidence-based insights:

  • Play is associated with lower cortisol levels and helps buffer daily pressure (American Academy of Pediatrics).
  • Adult playfulness supports positive emotion and resilience (Frontiers in Psychology, 2022).
  • Playful reframing of everyday routines promotes positive affect and stress relief (Proyer et al., PMC).

Design Goals

  • Stress Reduction: No "right answers," short playful prompts, optional engagement.
  • Emotional Awareness: Mood icons, imaginative questions, and quick check-ins.
  • Reframe Routine: Dress-up as a daily ritual instead of a task.
  • Encourage Autonomy: User chooses how much to write, draw, or interact.

Information Architecture

  • Open Diary → Meet Companion → Dress Ear → Reflect → Save Memory
  • Decision branch: Save Memory → Yes (Save Entry) / No (Exit without saving)

User Flow & Accessibility

The user flow was designed horizontally to reflect UX industry standards, with WCAG accessibility considerations embedded at each screen step — not as an afterthought, but as part of the design process from the start.

  • Meet Companion: Alt text for companion image.
  • Dress Companion: Color not used as sole indicator; tap targets minimum 44×44px.
  • Reflection Page: Text contrast 4.5:1 minimum; large text support.
  • Memory Archive: Readable without color; alt text included.

Design System

A scalable design system was built to ensure visual cohesion across all screens. All color tokens were verified against WCAG AA contrast standards using WebAIM Contrast Checker.

Color Tokens

  • Muted Lavender — Primary · CTAs, buttons, active states
  • Sage Green — Primary · CTAs, buttons, focused states
  • Warm Cream — Secondary · Sub-links, filters, tabs, card backgrounds
  • Forest Green — Secondary · Navigation active, accent
  • Soft Peach — Secondary · Tags, highlights
  • Charcoal — Neutral · Primary text and icons
  • Dark Navy — Neutral · Headings, surface contrast
  • Slate Gray — Neutral · Secondary text, disabled states
  • White — Neutral · Backgrounds, card surfaces

All color pairings meet WCAG AA minimum contrast ratio of 4.5:1 for normal text. Verified via WebAIM Contrast Checker.

Typography

  • Heading 1 — Nunito ExtraBold · 48px · Letter Spacing -2% · Titles
  • Heading 2 — Nunito Bold · 32px · Letter Spacing -1% · Screen headers
  • Body — Inter Regular · 16px · Letter Spacing 0% · General text
  • Body Emphasis — Inter Medium · 16px · Button labels, highlights
  • Prompt — Caveat Regular · 18px · Letter Spacing 1% · Diary entries
  • Caption — Inter Regular · 12px · Letter Spacing 2% · Labels, dates

Accessibility (WCAG AA)

  • All text contrast ratio 4.5:1 minimum
  • Touch targets minimum 44×44px (WCAG 2.1 AA)
  • Icon size minimum 24×24px within 44×44px touch area
  • Color never used as sole meaning indicator
  • Icons paired with text labels
  • Large text support enabled across all screens
  • Verified via WebAIM Contrast Checker

Component Library

A scalable component library was built in Figma to support the dress-up interaction system. Each clothing item was structured as a named component using hierarchical slash notation, with color variants grouped into component sets for efficient reuse across screens.

  • Tops — Hoodie, T-shirt, Sweater, Coat, Puffer, Dress, Blazer, Cardigan
  • Bottoms — Pants, Skirt, Sweats, Shorts (multiple color variants each)
  • Accessories — Cap, Beanie, Glasses, Headphones, Socks, Shoes, Boots

Component naming follows the pattern Category/Type/Color (e.g., Tops/Hoodie/Gray, Acc/Cap/Black) enabling fast lookup and variant switching during prototyping.

UI Screens — in progress

Five core screens were designed for iPhone (390×844px), each addressing a distinct moment in the daily ritual. The visual language is grounded in sage green and warm cream tones, with Ear's illustrated presence carrying emotional continuity across the flow.

Splash Screen

A full-bleed sage green background with a centered white arch frames Ear standing still. The app name "Wearby" appears above in dark navy with "ear" visually highlighted, introducing both the brand and the character name in a single moment before the user enters the app.

Screen 1 — Home

A sage green header greets the user with "Welcome :)" and the prompt "What did Ear wear today?" Ear appears top-right in a compact form. Below, a large warm cream card reads "Dress Ear today. Haven't picked an outfit yet?" with a forest green "+" CTA. A thinner card below summarizes the week ("You've logged 3 outfits this week."). A Recent Memories section shows scrollable thumbnails of past outfits by date. The bottom navigation bar includes Home, Stats, Help, and Profile tabs.

Screen 2 — Dress Companion

Ear stands center-screen on a clean cream background, ready to be dressed. Floating action buttons on the left of Save (bookmark icon) and Reflect (pen icon) are labeled for accessibility. A bottom panel organizes clothing by category tabs: Tops, Bottoms, Outers, Acc, Shoes. Items are displayed in a 3-column grid. When an item is tapped, it immediately appears on Ear's body to demonstrate the real-time dress-up interaction. The selected item in the grid receives a soft, rounded highlight. This screen shows a white tee applied to Ear, with the grid updated to reflect the active selection state.

Screen 3 — Reflect

A clean white screen titled "How was today? :)" invites the user to reflect after dressing Ear. Two speech-bubble-style input cards prompt: "One thing I'd keep from today:" and "One thing I can leave here:" — the first pre-filled with a handwritten-style note ("Had sushi with friends.") to demonstrate the Caveat font in context. Below, a "Today's Mood:" star rating row (5 stars, tap to select) rounds out the emotional check-in. At the bottom, two pill buttons sit side by side — "Skip for now" (with a skip icon) and "Save this memory!" (with a checkmark) giving users full autonomy over whether to save. Text contrast meets WCAG AA 4.5:1 across all labels and input fields.

Screen 4 — Final

A full-bleed crumpled paper texture serves as the background, giving each saved memory a tactile, handmade quality. Ear stands dressed in the saved outfit of sunglasses, white tee, gray pants, white sneakers. The date (03/10) appears top-right. At the bottom, a card shows the day's record: mood rating (star icons, 4 out of 5) and a brief reflection note: "Had sushi with friends." written in a casual handwritten-style font.

Physical Companion & Packaging — in progress

The digital experience is designed to extend into a physical artifact — a pocket-sized dress-up diary with outfit stickers, background scene cards, and daily reflection prompts. The "surprise" packaging will reveal Ear alongside a curated set of sticker outfits, creating a tactile onboarding experience that mirrors the app's welcome flow. Physical production is currently in progress.

Reflection — in progress

This project is still actively being built, but it has already shifted how I think about design systems. Building the component library first — naming conventions, variant logic, token structure — before touching the UI screens forced a discipline I hadn't fully practiced before. Every decision downstream became faster and more consistent because the system existed upstream.

Embedding WCAG from the user flow stage, rather than retrofitting it at the end, also changed my perspective. Contrast ratios, tap targets, and label pairings stopped feeling like compliance checkboxes and started feeling like design decisions — ones that make the product better for everyone, not just edge cases.

Next steps include completing the high-fidelity UI screens, building the Figma prototype with Smart Animate transitions, and exploring Figma Make to generate component code. The goal is a fully interactive prototype that communicates not just what Wearby looks like, but how it feels to use.
