Wearby

A Playful OOTD Diary Companion for Daily Reflection and Emotional Well-Being

The Problem

Daily reflection tools feel serious and effortful. Users who want gentle emotional check-ins have no tool that feels approachable, low-pressure, or fun.

The Solution

A mobile companion app where dressing up a character named Ear becomes a daily ritual — turning reflection into play rather than a task.

Role
UX/UI Designer · Design Systems · Interaction Design
Type
Individual · Ongoing
Timeline
Feb 2026 – Present
Tools
Figma · Procreate · Adobe Photoshop · Cricut

Key Design Decisions

Three choices that defined the direction — each grounded in research, not preference.

01

Play over journaling

Research shows play lowers cortisol and supports emotional resilience in adults. Dressing up Ear creates a low-pressure emotional state where reflection happens naturally — without the intimidation of a blank page.

02

System before screens

The component library and design tokens were built before any UI screen. Naming every clothing component Category/Type/Color (e.g. Tops/Hoodie/Gray) made variant switching fast and consistent — every downstream decision got easier.

03

Accessibility from the start

WCAG AA was embedded at the user flow stage, not retrofitted. Contrast ratios, 44×44px tap targets, and label pairings were design decisions — not compliance checkboxes — making the product better for all users.

Process

Research → Design Principles

Secondary research grounded every feature in evidence:

  • Play lowers cortisol and buffers daily pressure (American Academy of Pediatrics)
  • Adult playfulness supports positive emotion and resilience (Frontiers in Psychology, 2022)
  • Playful reframing of routine promotes stress relief (Proyer et al., PMC)

This led to four design principles: reduce pressure, build emotional awareness, reframe routine as ritual, and give users full autonomy over engagement depth.

User Flow & Information Architecture

The flow was mapped horizontally to reflect industry standards, with WCAG accessibility considerations annotated at each step — not added at the end.

Open Diary → Meet Ear → Dress Ear → Reflect → Save Memory (or Skip)

Design System

A scalable token-based system was built before any screens were designed — ensuring visual cohesion and WCAG AA compliance across all surfaces. All color pairings verified via WebAIM Contrast Checker.

Component Library

Every clothing item was structured as a named Figma component using hierarchical slash notation (Category/Type/Color), with color variants grouped into component sets. This enabled fast lookup and consistent variant switching across all screens.

UI Screens — in progress

Five core screens designed for iPhone (390×844px). The visual language uses sage green and warm cream, with Ear's presence carrying emotional continuity across the flow.

Physical Companion — in progress

The digital experience extends into a pocket-sized physical diary with outfit stickers, background scene cards, and daily reflection prompts. Surprise packaging reveals Ear alongside a curated sticker set — mirroring the app's welcome flow as a tactile onboarding experience.

Reflection

Building the component library before touching any UI screen forced a discipline I hadn't fully practiced before. Every downstream decision became faster because the system existed upstream. Embedding WCAG from the user flow stage — rather than retrofitting it — also changed my perspective: contrast ratios and tap targets stopped feeling like compliance and started feeling like design decisions that make products better for everyone.
